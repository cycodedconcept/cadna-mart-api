# M2 — Catalogue, categories and home data

Implemented 2026-11-22. No push performed.

## Scope

- Public `GET /api/v1/categories`, `/products`, `/products/:id` and `/home` routes with zod input validation, AppError envelopes and generated OpenAPI.
- Prisma categories/products plus ordered images and named specifications. Products default to unpublished; every product read requires publication and an active category.
- Integer-kobo prices stored as unsigned BIGINT, with SQL checks limiting both prices to JavaScript's safe integer range and requiring originalPrice >= price. Unsigned stock prevents negative inventory.
- Name search, category, inclusive price and stock filters, deterministic name/price sorting and eight-item pagination. Out-of-range pages clamp to the last page, matching the existing storefront behavior.
- Repeatable-read list/home transactions. Home returns active categories, up to eight featured published products and an empty reserved banners array.
- Integration tests cover all four public endpoints, invalid inputs, database failure envelopes, hidden products, exact money, ordering, pagination, literal wildcard search and database constraints. Test cleanup includes catalogue tables only in the guarded test database.
- Updated README and implemented API contracts. No dependencies changed; the existing lockfile remains applicable.

## Limitations and integration

- No frontend files changed. Clients must replace numeric product IDs/category slugs with UUID strings and convert display naira to/from integer kobo. Empty search strings should be omitted.
- No mock stock or products are seeded. Apply the migration and provision catalogue records through a trusted operator until M7 admin management is implemented. The existing settings seed remains idempotent.
- Home banners are intentionally empty pending M8 content requirements. No CMS, admin mutation routes, upload workflow or seller model is introduced here.
- M3 will calculate cart quotes from these server prices; stock reservations, variants and checkout are not implemented.
- Category lists are unpaginated; substring searches and large page offsets may need dedicated indexing/search infrastructure at scale. Image URLs are stored references; no image fetching occurs.
- SQL CHECK constraints are migration-managed because Prisma's schema does not represent them. Preserve them in future migrations. Integration testing uses MariaDB; GitHub CI and other database versions were not run locally.
- No development/production database migration or data changes were performed. Live SMTP and previous dependency audit findings are outside this milestone.
