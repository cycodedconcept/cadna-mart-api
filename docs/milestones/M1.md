# M1 — Authentication and customer profiles

Completed 2026-11-17. No push performed.

## Scope

- Customer registration, scrypt password hashing, opaque database sessions, logout and session inspection.
- Owned customer profile reads/updates; email changes require the current password and revoke sessions.
- Password recovery with hashed single-use tokens and an encrypted transactional email outbox; file delivery for development and SMTP worker for production.
- Separate admin sessions with mandatory TOTP enrollment/verification, replay protection, single-use recovery codes and explicit role checks. Trusted operator admin creation reads credentials from stdin.
- Authentication migration, zod-generated OpenAPI, documented browser headers/cookies, account throttles, CI configuration and environment examples.
- Continued the existing unfinished implementation, corrected formatting, validated the browser client header through zod, and corrected the expiry test to exercise a real expired reset token.

## Validation

- `npm run validate`: passed formatting, lint, strict typecheck, all 57 tests across three files, and production build.
- MariaDB integration tests apply migrations exclusively through `DATABASE_URL_TEST`, guarded to require a separate database ending in `_test`.
- Coverage includes invalid inputs, absent/expired sessions, customer/admin isolation, admin role checks, CSRF, profile ownership, duplicate emails, recovery expiry/revocation, concurrent reset/MFA consumption, replay protection and mail retry/claim behavior.
- Initial sandbox execution could not access MariaDB or bind HTTP test sockets. Validation succeeded with approved access.
- No development migration deployment, real SMTP send or frontend integration was performed during this continuation.

## Limitations

- SSO, email verification, trusted devices, MFA rotation and recovery-code regeneration are not implemented. `rememberDevice` is accepted without extending the fixed 30-minute admin session.
- Lost MFA plus lost recovery codes requires a separately designed operator recovery procedure; password reset intentionally does not disable MFA.
- File mail contains sensitive recovery links and is development-only. Production requires SMTP and HTTPS application URLs. Encryption-key rotation needs a migration strategy.
- Mail delivery is at-least-once: a worker crash after sending can cause redelivery. Five failed attempts stop retries until the job expires; delivery monitoring and operator retry tooling remain follow-up work. Real SMTP transport was not exercised; tests inject delivery behavior.
- Expired session/challenge/reset/throttle records need a scheduled retention job. Expired outbox records are removed by the mail worker.
- IP limits remain per-process and proxy trust is disabled; account throttles are database-backed. SameSite=Lax requires same-site browser hosting.
- The existing M0 dependency-audit findings were not re-audited in this continuation. Prisma 6 still emits its package.json configuration deprecation notice.
